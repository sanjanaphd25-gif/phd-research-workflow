### Q1. How does Git help in maintaining research traceability?
A: Git provides a permanent, comprehensive audit trail of all code modifications in your research. Each commit captures a project snapshot, including the author, timestamp, and change description. This history is crucial for tracing unexpected changes months later; Git lets you compare file versions line-by-line to pinpoint the exact modification that altered your results. 
### Q2. Why is GitHub useful for academic collaboration?
A: GitHub centralizes global sharing and peer review, facilitating asynchronous collaboration across time zones. Beyond code hosting, it offers project management tools like Issues (for tracking bugs/tasks) and Project Boards (for workflow organization). It also makes your findings public via a repository, serving as a portfolio that boosts your lab's visibility and impact within the global scientific community. 
### Q3. Why should researchers create branches instead of working directly on main?
A: Branches isolate experimental changes from stable code. The main branch is the "source of truth"—the working, stable version. Creating a branch (e.g., feature-data-cleaning) provides an independent sandbox to aggressively alter scripts or test hypotheses without breaking the baseline. If the experiment fails, delete the branch; if it succeeds, merge it. 
### Q4. What is the role of Pull Requests in collaborative work?
A: Pull Requests (PRs) function as an essential internal peer-review system for code verification before merging. When a branch is complete, a researcher opens a PR to propose merging changes into the main project. This creates a forum for co-authors to inspect code changes, ask questions, suggest optimizations, and catch errors. PRs enforce transparency and rigorous quality control, preventing primary project corruption. 
### Q5. Why are reproducibility files important in research repositories?
A: Reproducibility files (like requirements.txt, scripts, data) are crucial for peers to perfectly replicate research results. Since software libraries change, these files specify the exact dependency versions, ensuring that the computational environment can be reconstructed precisely to run scripts and achieve identical results, even years later.
### Q6. What is the purpose of creating a version tag such as v1.0.0?
A: Tagging code (e.g., v1.0.0) creates a permanent snapshot of the project's state at a specific milestone, such as publication. This fixed, unbreakable link ensures reviewers and readers access the exact version of the code that corresponds to the published work, even as the repository continues to evolve. 
### Q7. Why should a repository include a citation file?
A:To ensure creators receive academic credit, make software and datasets easily citable as research outputs. Citing GitHub repositories can be difficult for researchers. Including a CITATION.md or a BibTeX entry in your README.md simplifies this. This standardization allows reference managers to automatically extract citation details, increasing the chance your work is formally recognized and cited.
### Q8. How does this semester’s Git/GitHub workflow support better PhD research practice?
A: Adopting a Git/GitHub workflow eases PhD research by ensuring reproducibility, security, and structured progress. It provides a verifiable ledger of every project change—scripts, data processing, and manuscripts—allowing instant inspection or reversion to earlier states. GitHub offers secure, cloud-based backup against data loss. Pull requests facilitate structured collaboration and feedback. This version control shifts PhD work from chaotic files to a professional, transparent, and manageable lifecycle, drastically reducing stress and enhancing research integrity.
